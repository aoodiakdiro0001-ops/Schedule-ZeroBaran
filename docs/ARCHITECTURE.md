## المبادئ التصميمية

1. **Separation of Concerns (فصل المسؤوليات):** كل طبقة تتعامل مع مسؤولية واحدة فقط.
2. **Stateless API:** الـ API لا يحفظ حالة الجلسة، مما يسهّل التوسّع.
3. **Idempotent Operations:** إعادة تنفيذ نفس طلب الحجز لا تُحدث تعارضاً (لوجود فحص التعارض).
4. **Fail-Safe:** عند فشل طبقة الذكاء الاصطناعي، يُستخدم رد افتراضي (لا يتعطّل النظام).
5. **Configuration-Driven:** كل الإعدادات في `.env` ولا تُكتب في الكود.

## الخصائص الرئيسية

### منع التعارض (Conflict Prevention)
عند محاولة حجز موعد، يفحص النظام قاعدة البيانات لجميع المواعيد المؤكدة أو قيد الانتظار في نفس اليوم، ويتحقق من عدم وجود تداخل زمني. الفحص يحدث **atomic** لتفادي السباق.

### الإتاحة الديناميكية (Dynamic Availability)
يحسب النظام الفترات المتاحة بـ:
- قراءة ساعات العمل لليوم المطلوب.
- استبعاد الاستثناءات (إجازات).
- استبعاد الفترات المحجوزة.
- توليد خانات زمنية (slots) بحسب مدة الخدمة.

### التذكيرات الآلية (Automated Reminders)
- يُشغّل GitHub Actions دورة كل ساعة.
- يفحص المواعيد المؤكدة ضمن النافذة الزمنية (ساعة قادمة).
- يُرسل تذكيراً عبر تليجرام ويُسجّل في `notifications_log`.
- يحدّث عمود `reminder_sent = true` لتفادي التكرار.

### النشر متعدد البيئات
- **محلياً:** `uvicorn app.main:app`
- **Vercel Serverless:** `api/index.py` مع `vercel.json`
- **خادم خاص:** Gunicorn + Uvicorn workers
